# 文档编辑规范

> 版本: v1.0
> 适用: docs/ 目录下所有文档

## 一、编辑流程

```
① 对齐（口头/消息）  →  ② 确认  →  ③ 写入文档
```

**禁止**：未与用户确认就直接编辑文档。每一次文档变更前，必须先让用户知晓改什么、为什么改，得到确认后再动笔。

## 二、内容规则

### 2.1 只写已确认的事实

- ✅ 已跑通验证的技术结论
- ✅ 用户明确确认的决策
- ❌ 待确认/待讨论的事项
- ❌ 未验证的假设或推测
- ❌ 伪代码、示例代码（文档是规格说明，不是实现预览）

### 2.2 不含伪代码

文档描述「要做什么」和「怎么判断做对了」，不描述「怎么写代码」。函数签名和数据结构可以写，但不写实现逻辑。

### 2.3 已过时的内容归档

以 `.archive-` 前缀移到 docs/ 同目录，不在活跃文档中保留。

## 三、开发流程

```
① 文档梳理（需求/设计）  →  ② 对齐确认  →  ③ 代码编写
```

**禁止**：文档未对齐就开始写代码。文档是开发的唯一依据。

## 四、文档必须包含的章节

每篇文档必须包含：

- **交付物**：产出什么，路径在哪
- **价值**：做完能做什么，不能做什么
